# 成员独立投票码投票系统

Python 3.10+，仅使用标准库，无需安装依赖。数据保存在服务器的 SQLite 数据库中，不再使用各浏览器的 localStorage。

## Ubuntu 公网部署

目标目录 `/root/clf/wechat/wechat-vote-mvp`，当前默认监听 `0.0.0.0:18080`，通过 `http://公网IP:18080/` 直接访问，不需要 Nginx。部署步骤见 [deploy/UBUNTU.md](deploy/UBUNTU.md)，已提供 systemd 服务及后续可选的 Nginx 配置。数据库持久化到 `/var/lib/wechat-vote/votes.sqlite3`。

## 启动

Windows 可双击 `start.cmd` 启动（本机优先使用已随 Codex 配备的 Python），保持启动窗口打开。在其他已安装 Python 的电脑，也可在项目目录运行：

```powershell
python server.py
```

打开终端显示的 `http://localhost:8000`。管理员密码显示在启动窗口中；默认每次重启生成新的管理员密码，已有投票码和票据保持不变。需要固定密码时，启动前设置环境变量 `VOTE_ADMIN_PASSWORD`，不要把密码写进代码或提交到仓库。

同一 Wi-Fi 下，其他手机访问 `http://电脑的局域网IP:8000`，例如 `http://192.168.1.20:8000`。电脑须保持运行，防火墙须允许该端口；路由器若开启设备隔离则需关闭隔离或换网络。不能把 `localhost` 地址发给其他人，也不能直接双击 HTML 使用共享投票。

若成员不在同一局域网，需要把本服务部署到可访问的服务器，并通过 HTTPS 反向代理对外提供服务。当前项目未部署到公网，不会自动生成公网地址。投票码和管理员密码均属于凭证，公网使用须通过 HTTPS 传输。

可选参数：`python server.py --host 127.0.0.1 --port 8000 --db votes.sqlite3`。默认监听 `0.0.0.0:8000`。

## 使用流程

1. 管理员登录“管理”页，新增至少三支队伍，每队录入 1～3 名成员，每行一人。人数由成员名单自动确定。
2. 系统为每位成员生成随机的 16 位独立投票码。可导出 CSV，向每人单独发送自己的码，不要把完整名单发到群里。
3. 队伍数量不限（至少三队，每队 1～3 人）。核对成员名单后点击“开放投票”。开放期间不能添加；暂停后可追加新队伍，不能修改或删除原队伍。旧票保留且不能重投，因此建议正式投票前录完全部队伍。
4. 成员打开同一个服务器地址，输入投票码，确认姓名和所属队伍。选择两支不同的其他队伍，提交后不能修改。
5. 管理员可暂停或重新开放投票。排名仅在管理员登录后显示，公开接口不返回得分或名次。页面每 15 秒刷新活动状态，管理员可手动刷新排行。切换投票码后两票均清空，不继承上一位成员的选择。

投票码是持有者凭证：系统能校验该码属于哪个成员与队伍、该成员是否已投，不能确认操作者本人。不要共享投票码。SQLite 唯一约束和事务保证同一成员并发提交时只记录一次。

每票权重为 `1 / (2 × 本队成员数)`，成员各投两票；全员完成时每队共分配 1 分。相同得分并列名次。

旧 HTML 的浏览器本地数据不会自动导入；请重新录入成员名单。备份时先停止服务，再复制 `votes.sqlite3`。文件包含投票码与票据，应限制访问。开始新活动请停止服务并使用新的 `--db` 文件，保留旧库作为备份。
